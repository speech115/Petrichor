# Petrichor

Один проект, два таргета: Petrichor (macOS) и PetrichoriOS (iPhone). Оба показывают
одну и ту же локальную библиотеку: треки из тегов, порядок плейлистов из M3U.

## Language

**Канон названий**:
Название трека — из тега `title`; имя файла — только фолбэк при пустом теге.
Числовой префикс в имени файла (`0239 - Jeune Ras - Ruff Ryder`) — атрибут
порядка в плейлистах, а не название.
_Avoid_: «название файла» как синоним названия трека

**Плейлист**:
Порядок треков, заданный позицией в M3U-файле. Импортированный плейлист
живёт после удаления своего M3U-файла.
_Avoid_: синхронизируемый файл, «импорт заново»

**Вся музыка**:
Полная локальная библиотека с общей настройкой скрытия дублей. Импортированный
плейлист «Все треки» не подменяет этот раздел и сохраняет своё имя и порядок.

**Избранное Petrichor**:
Встроенный Favorites: треки, отмеченные сердечком в приложении. Любимые треки
из VK и Spotify остаются отдельными импортированными плейлистами.

**Смарт-плейлист**:
Плейлист, пересобираемый правилами (Favorites, Top 25 Most Played, Top 25
Recently Played).

**Реконсиляция**:
Фоновое приведение базы в соответствие с файловой системой Documents.
Запускается по триггерам (запуск приложения, возврат из фона, кнопка
«Пересканировать»), пропускается, если файлы не менялись. Пропавший файл не
удаляет строку трека — база канон, а не зеркало файловой системы.
Противопоставляется «сканированию при каждом запуске».
_Avoid_: «скан при запуске», «рефреш библиотеки» для запуска

**Home**:
Первая из четырёх вкладок iPhone: «Продолжить с места остановки», недавно
игранные альбомы и блок Library. Переименована из «Библиотека».
_Avoid_: «Библиотека» как имя вкладки

**Discover**:
Раздел рекомендаций: 50 непрослушанных треков (playCount = 0, без дублей),
обновляется раз в неделю. Логика общая с маком, на iPhone — отдельная вкладка,
показанная как плейлист.
_Avoid_: «полка Discover» — на Home её больше нет

**M3U**:
Файл плейлиста с относительными путями от корня переносимой папки. Источник
обычных плейлистов на iPhone.

**Источник плейлиста**:
Сервис, из экспорта которого плейлист приехал — Spotify, VK, Яндекс Музыка.
Читается из имени плейлиста, задаёт секцию во вкладке Playlists. Знак сервиса
живёт в заголовке секции, не в строках.
_Avoid_: «папка плейлиста», «категория плейлиста»

**Закреплённый плейлист**:
Плейлист, чьи членство в секции, позиция, показанное имя и обложка заданы
списком в коде (`PlaylistSource.pinned`), а не выведены из имени. Временная
конструкция поверх данных, которые уже есть в перенесённой базе.

**Трековая обложка**:
Обложка, лежащая в `track_artwork_data` самого трека, а не в его альбоме. У
404 треков это единственная обложка, и в файлах её нет — она появилась при
ремонте маковской базы. Списки подгружают её построчно, а не пачкой.
_Avoid_: «обложка альбома» как общее слово для любой обложки

**Сведения о треке**:
Лист с метаданными одного трека: обложка, названия, теги, файловые свойства.
Только чтение — правка тегов с телефона не предполагается. На iPhone написан
заново, макосный `TrackDetailView` не переиспользуется.
_Avoid_: «карточка трека», «детали трека»

**Группа дублей**:
Набор строк треков, указывающих на побайтово одинаковые файлы
(`duplicate_group_id`). Внутри одного плейлиста повторы схлопываются до
первого вхождения. Не путать с настройкой «Hide duplicate songs», которая
прячет неглавные копии по всей библиотеке и вырезает треки из плейлистов.

**Перенос библиотеки**:
Замена базы телефона копией маковской с переписыванием путей. Не то же, что
пересканирование: часть библиотеки существует только в базе и в файлах её нет.
См. `docs/adr/0003-library-copied-from-mac.md`.
_Avoid_: «синхронизация с маком» — переноса обратно нет
