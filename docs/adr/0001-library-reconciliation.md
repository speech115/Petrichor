# База — канон отображения, файловая система реконсилируется в фоне

При запуске iPhone UI читает только базу и показывает библиотеку мгновенно;
сканирование Documents превращено в фоновую реконсиляцию, которая запускается
по триггерам (запуск, возврат из фона, кнопка «Пересканировать»), делает
дешёвую проверку изменений и пропускается, если ничего не изменилось. Полный
скан с прогрессом — только при пустой базе (первый запуск) или принудительно.

Причина: прежний порядок — полный обход файловой системы, чтение и сжатие
обложек и пост-шаги (дубли, нормализация, статистика) при каждом запуске —
давал ожидание на старте. Аналог — Spotify/Apple Music: кэшированная библиотека
показывается сразу, синхронизация идёт фоном. Trade-off: свежесть библиотеки
отстаёт от копирования файлов через Finder до ближайшего триггера.

## Пропавший файл не удаляет строку трека

Проверка изменений (`libraryContentsDiffer`) считает отсутствие файла на диске
не изменением, и полный скан тоже не сносит строку: база — канон, файловая
система реконсилируется, а не наоборот. Удаление строк при скане
(`removeDeletedTracks`) — устаревший путь, вычищается. «Недоступность» трека
ничем не помечается: строка живёт, ошибка возникает при воспроизведении.
Trade-off: в библиотеке остаются треки без файла до ручного удаления.
