# library-motion — итог

Спека: `spec.md`. Следующая итерация после `.scratch/player-defects/`.

Пять тикетов закрыты, один открыт и ждёт проверки пальцем. Сборка и 66/66
тестов зелёные, коммит `35ce1ee` в `origin/ios-port`, сборка установлена и
запущена на iPhone.

## Что сделано

| Тикет | Что двигается | Чем закрыт |
|---|---|---|
| 01 | Обложка проявляется на декоде, а не подменяется | по коду: ветка кэша не тронута |
| 02 | Обложка и названия плеера едут в сторону движения по очереди | покадрово: ~190 мс промежуточных положений |
| 03 | Спиннер списка ждёт 200 мс, прежде чем появиться | по коду |
| 04 | Иконка мини-плеера морфит как транспорт | по коду |
| 05 | Названия мини-плеера сменяются кросс-фейдом | скриншот: раскладка цела |

## Что открыто

- **06 — отдача на нажатие строки трека.** Единственный пункт аудита, который
  не решается ни кодом, ни симулятором. Если её нет — это важнее всех пяти
  сделанных правок; рецепт в тикете.
- **Морф обложки мини → полный экран.** Разобрано в `spec.md`: сознательно не
  берётся, потому что это пятый заход на переход, который только что приняли.
- Канон дизайна не трогался: новых экранов и элементов здесь нет, только
  поведение существующих. В прошлой итерации канон дополнялся, потому что
  добавлялся экран.

## Что стоит помнить, читая эту директорию

Таблица отклонённых кандидатов в `spec.md` — не приложение к работе, а её
половина. Она существует, чтобы следующий агент не «дополнил» приложение
анимацией результатов поиска, каскадом на Home или тикающими цифрами в
скраббере. Каждый из этих кандидатов рассматривался и отклонён по частоте.
