# Спека: восемь пунктов до «официального порта»

Дата: 2026-08-09. Статус: **in-progress**, тикеты 01–07 открыты.

## Зачем

Ревью ветки `ios-port` под линейкой «как если бы это был официальный порт от
разработчика» дало восемь пунктов, которые владелец утвердил к реализации.
Цель — **не** предложение апстриму: форк остаётся личным, «официальность» —
мерило качества. План согласован через полный grilling-проход (40 вопросов,
5 раундов); решения ниже — итог этого прохода, их не пересматривают по ходу
реализации без возврата к владельцу.

## Вне области — сознательно

- Личные плейлисты, захардкоженные в `iOS/Playlists/PlaylistSource.swift`, и
  чужие бренды в `Resources/Assets.xcassets` — для личной сборки это фича.
- Путь «как музыка попадает в приложение» для нового пользователя — библиотека
  переносится с мака (ADR 0003), другого пути не требуется.
- Handoff — требует одного Team ID на оба таргета, а macOS-таргет менять
  нельзя (смена = новый sandbox = потеря библиотеки). Только CoreSpotlight.
- Вкладка «Папки» на iPhone — не возвращается; спека дизайна замораживается с
  явной пометкой (тикет 02).
- Синк мак→телефон — уже обслужен переносом библиотеки целиком.
- `rating` и позиция воспроизведения в журнале — rating на iPhone не
  выставляется, позиция = Handoff.

## Ключевые решения (свод grilling-прохода)

| Тема | Решение |
|---|---|
| Спека дизайна | Замораживается как исторический документ; живое состояние — `CONTEXT.md`. Правило «расхождение — дефект кода» для неё снимается (тикет 02 правит CLAUDE.md) |
| Синк | Односторонний телефон→мак. Append-only JSONL журнал событий (`played`, `favorite`) в `Documents/Sync/playback-journal.jsonl`, один файл, без ротации |
| Ключ сопоставления | Относительный путь от корня библиотеки — тот же, что у переноса и M3U |
| Идемпотентность | Курсор: время последнего применённого события, хранится на маке |
| Запись журнала | Пакетом при уходе в фон, рядом с `savePlaybackState()`, не при каждой мутации |
| Пятый шов | `PlaybackJournal`-протокол: пишущая реализация на iOS, no-op на маке. По образцу `scrobbleManager` (`Application/AppCoordinator.swift:18`, `Managers/PlaybackManager.swift:50-51,723`) |
| События без пары | Пропускаются, но считаются; сводка «N событий не нашли трек» показывается на маке рядом с кнопкой применения |
| Swift 6 | Чинить до нуля на ветке, `SWIFT_STRICT_CONCURRENCY=complete` включается последним коммитом, тогда же CI-гейт «ноль предупреждений» на iOS. Мак обязан компилироваться, до нуля не доводится и не гейтится |
| Изоляция | `LibraryManager`, `PlaylistManager`, `PlaybackManager` — `@MainActor` целиком. `DatabaseManager`: `@Published`-состояние скана выносится в отдельный `@MainActor`-объект наблюдения (по образцу `presentationObservation` в `PlaybackManager`), остаток становится честно `Sendable`. Никаких `@unchecked Sendable` и `nonisolated(unsafe)` |
| AppIntents | `Managers/Automation` исключается из iOS-таргета (−194 предупреждения). Проверено: внешних ссылок на папку нет |
| Метаданные | `AVMetadataItem.value/.dataValue/.numberValue` → `load(...)` (−180 deprecation, минус блокирующий I/O в шве) |
| Spotlight | Треки + альбомы + артисты (плейлисты — нет: экспортные имена в поиске — мусор). Индекс инкрементально в реконсиляции + один фоновый полный проход с курсором при первом запуске. Удаление из индекса — только при удалении строки из базы, не при пропаже файла (ADR 0001). Маршрутизация — `CSSearchableItemActionType` → `LibraryDestination`, без URL-схемы |
| Доступность | Метки/объединение + Dynamic Type (21 фиксированный кегль). Гейт — `performAccessibilityAudit()` на четырёх экранах: Home, список треков, Now Playing, Settings. На Now Playing проверка контраста отключена (палитра из обложки). Без baseline-файла |
| CI-гейт | «Стартует → играет → мини-плеер и Now Playing на месте» на симуляторе; локскрин — вручную на устройстве (`MPNowPlayingInfoCenter` в симуляторе врёт). Release-сборка iOS — отдельная джоба на `workflow_dispatch` |
| Документация | `README-iOS.md` + 3 скриншота из симулятора; в апстримном `README.md` — одна строка-ссылка. ADR о расхождении форка; `upstream` remote подключается для будущего разбора, мерж не планируется |

**Поправка к решению о фикстурах.** Утверждённое «закоммитить три тихих mp3»
принималось на посылке, что генерация требует ffmpeg. Посылка ложна: в репо
уже есть `makeSilentMP3` (`Tests/PetrichoriOSTests/TestFixtures.swift:122`) и
прямо записанная традиция не хранить бинарные фикстуры. Тикет 01 переиспользует
генератор; бинарники в репозиторий не добавляются.

## План: семь тикетов = семь PR в `main`

| # | Тикет | Blocked by | Проверка |
|---|---|---|---|
| 01 | `01-ci-foundation` — фикстуры, рабочий smoke-тест, Release-джоба | — | CI + устройство |
| 02 | `02-docs-and-freeze` — README-iOS, заморозка спеки, ADR, upstream | — | ревью |
| 03 | `03-shrink-the-problem` — Automation вон из iOS, метаданные на `load()` | — | CI, замер предупреждений |
| 04 | `04-swift6-isolation` — `@MainActor`, `Sendable`, включение strict, гейт | 03 | CI на нуле |
| 05 | `05-playback-journal` — пятый шов, запись на iOS, применение на маке | 04 | CI + ручной прогон обеих сторон |
| 06 | `06-spotlight` — индекс в реконсиляции, роутер | — | устройство |
| 07 | `07-accessibility` — метки, Dynamic Type, аудит в CI | 01 | CI + устройство |

Порядок: 03 перед 04 (уменьшает задачу с ~700 до ~390 предупреждений), 04
перед 05 (шов ложится в уже изолированный код). 01, 02, 06 независимы.

Каждый тикет — отдельная короткая ветка от актуального `main`, PR
draft-ом после первого цельного коммита (см. CLAUDE.md «Ветки и PR»).
Устройство — через скилл `.claude/skills/petrichor-device/`, там, где
симулятор врёт: воспроизведение/локскрин (01), Spotlight (06), VoiceOver (07).

## Непроверенные допущения (риски)

1. ~~`DatabaseManager` Sendable без изменений~~ — **опровергнуто**: у него
   `@Published isScanning/scanStatusMessage` + throttle-таймер
   (`Managers/Database/DatabaseManager.swift:12-23`). Решение: вынос в
   observation-объект (тикет 04).
2. `performAccessibilityAudit()` на SwiftUI-иерархии с overlay-плеером —
   проверится первым тестом тикета 07; если оверлей ломает аудит, гейтить
   экраны без открытого плеера и разбираться отдельно.
3. Стоимость первого полного прохода индексации (2758 треков) — замерить в
   тикете 06; если заметна на старте, дробить курсор мельче.
4. Применение журнала трогает мак-UI без автоматических проверок — верификация
   тикета 05 на мак-стороне ручная, это единственное место без зелёного CI
   как доказательства.
