# 06 — CoreSpotlight: библиотека ищется из системного поиска

Status: ready-for-agent

## Проблема

2758 треков не видны системному поиску: найти музыку можно только изнутри
приложения. В приложении нет ни URL-схемы, ни обработки `NSUserActivity` —
открыть результат поиска нечем.

## Что сделать

**1. Индексация** (всё — в iOS-таргете; CoreSpotlight на маке не трогаем).
Индексируются **треки, альбомы, артисты**. Плейлисты — нет (экспортные имена
вида «05 Spotify - Shazam» в системном поиске — мусор; решение утверждено).

- Идентификаторы: `track:<id>`, `album:<albumId>`, `artist:<имя>` (у артиста
  стабильного id может не быть — тогда имя; проверить по
  `Models/`/`LibraryFilterItem`).
- Атрибуты: заголовок; для трека — артист и альбом в
  `contentDescription`; миниатюра — `artwork_thumbnail` альбома/артиста
  (уже посчитаны и лежат в базе). Для ~404 треков с только трековой обложкой
  (`track_artwork_data`, см. CONTEXT.md «Трековая обложка») — миниатюра через
  существующий thumbnail-механизм (`Utilities/`, см. `ArtworkThumbnailTests`),
  не полноразмерный BLOB.
- **Инкрементально из реконсиляции**: `iOS/LibraryReconciliation.swift:29`
  (`reconcileLibrary()`) уже знает, менялось ли что-то на диске — после её
  апдейтов индексировать только новые/изменённые треки. Плюс один **полный
  фоновый проход при первом запуске** с курсором прогресса в `UserDefaults`
  (прерванный доиндексирует с места остановки). Приоритет `.utility`, не
  раньше конца реконсиляции — не мешать холодному старту. **Замерить** время
  полного прохода на симуляторной фикстуре и записать в Comments (риск №3
  спеки: если заметно — дробить).
- **Удаление из индекса — только при удалении строки из базы**, не при
  пропаже файла (ADR 0001: база — канон, не зеркало). Найти реальные точки
  удаления треков: `grep -rn 'deleteTrack\|\.delete()' --include='*.swift' Managers/Database/`
  и снести индекс-записи там же. Реконсиляция строк не удаляет — из неё
  ничего не удалять.

**2. Маршрутизация.** В `iOS/ContentView.swift` —
`.onContinueUserActivity(CSSearchableItemActionType)`: достать идентификатор,
преобразовать в `LibraryDestination` (`iOS/Library/LibraryDestination.swift`):
`artist:` → `.artist(name:)`, `album:` → `.album(AlbumEntity)` (поиск entity —
как в существующем `albumEntity(for:)`, `iOS/ContentView.swift:280`),
`track:` → страница его альбома (`.album`), а не автозапуск — тап по
результату поиска не должен внезапно включать звук; трек без альбома →
`.allTracks`. Установить `selectedTab = .home`, `homePath = [destination]` —
ровно как это делает обработчик `.goToLibraryFilter`
(`iOS/ContentView.swift:133-141`). URL-схему **не** заводить.

## Критерии приёмки

- [ ] Обе схемы собираются, тест-сьют зелёный (новых юнит-тестов не требуется:
      UI-слой + системный индекс, наш тестовый периметр их не покрывает).
- [ ] Устройство (скилл `petrichor-device`): после установки и полного прохода
      поиск iOS находит трек, альбом и артиста с обложками; тап по каждому
      типу открывает правильный экран. Скриншоты в Comments.
- [ ] Время полного прохода индексации записано в Comments.
- [ ] Повторный запуск не переиндексирует всё заново (проверить по логу).
- [ ] `Managers/`, `Core/` без новых `#if os` — вся работа в `iOS/`.
