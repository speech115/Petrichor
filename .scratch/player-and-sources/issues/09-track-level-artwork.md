# 09 — Трековая обложка в iOS-списках

**What to build:** Строки треков и превью-мозаики показывают обложку, которая
висит на треке, а не на альбоме.

В библиотеке 403 таких трека в одном только «ВКонтакте» (плюс 448 вообще без
альбома). iOS-строки читали `track.displayArtwork` = альбомная миниатюра или
альбомный полноразмер, и трековую не видели никогда; мак идёт другим путём
выборки и показывает.

Не «дозагрузить всё в список»: 404 трековые обложки по 72 КБ — это ~29 МБ
блобов, которые список никогда не показывает целиком. В коде уже был готовый
`getArtworkData(albumId:trackId:)` с комментарием «строки подгружают по одной,
по мере появления», который на iOS никто не вызывал. `ArtworkTile` получил
необязательный `loader`, `TrackRow` его передаёт для строк без обложки.

Превью-мозаика (`getPlaylistPreviewTracks`) добирает трековую обложку сразу —
там максимум четыре строки, и без этого мозаика пустая, а плейлист носит
заглушку-нотку.
