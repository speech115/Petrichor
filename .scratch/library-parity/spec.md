# Паритет библиотеки — решения

Из грилла (2026-08-07). Спека и ADR — канон; этот файл — краткая память о том,
что было решено и почему.

## Проблема

На iPhone не было 13 обычных плейлистов (импорт M3U никогда не запускался),
библиотека, вероятно, неполная от старого скана. При запуске каждый раз шёл
полный обход файловой системы — ожидание на старте.

## Решения

- Названия треков — из тегов, как на маке; имя файла — только фолбэк.
  Числовой префикс — атрибут порядка в плейлистах, не название.
- Порядок: плейлисты по позиции M3U, «Все треки» и папки по названию,
  альбомы по номерам треков.
- Запуск мгновенный: UI читает только базу; полный скан — только при пустой
  базе. Реконсиляция по триггерам: запуск, возврат из фона, кнопка
  «Пересканировать». Дешёвая проверка изменений, пост-шаги и обложки — только
  при реальных изменениях. (ADR-0001)
- Автоимпорт M3U из `Documents/Petrichor-Playlists` при реконсиляции: новые
  импортируются, изменённые обновляются, удалённые файлы плейлисты не сносят.
  (ADR-0002)
- Смарт-плейлисты (Favorites, Top 25) остаются — пересобираются правилами.
- Вкладка «Библиотека» переименовывается в Home; в Home добавляется Discover —
  50 непрослушанных треков, раз в неделю (общая логика с маком).
- Библиотека выросла: 2923 трека (2918 mp3 + 5 m4a), 13 M3U-плейлистов
  (уже переписаны в относительные пути `../Spotify/...`).

## Приёмка

2923 трека, 13 M3U + 3 смарт-плейлиста, порядки как на маке, мгновенный
запуск, подхват новых файлов после foreground.
