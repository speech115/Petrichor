# Petrichor iPhone — визуальный редизайн «как Apple Music»

Дата: 2026-08-07
Статус: **утверждена**

Дополнение к канону `docs/superpowers/specs/2026-08-05-petrichor-ios-design.md`.
**Замещает** в нём разделы «Интерфейс → Каркас» (состав вкладок), «Интерфейс →
Списки» (состав Home) и «Проверка → Автотесты» (добавляется пятое место теста —
шов миниатюр) — см. отметки ниже. Остальные разделы канона (швы, пути,
воспроизведение, сеть) в силе без изменений. После утверждения этот документ
становится каноном для перечисленных экранов.

## Зачем

Интерфейс функционально закрыт, но выглядит как плотный служебный список, а не
как Apple Music. Задача фазы — привести визуальную культуру к Apple Music,
сохранив локальную природу плеера и не жертвуя отзывчивостью.

## Ориентир

Смесь с **«Медиатекой» Apple Music как базой**: локальная коллекция живёт в
плотных быстрых списках с миниатюрами и крупными сворачивающимися заголовками.
Карточно-каруссельный приём «Home/Слушать» применяется **точечно** — только для
Discover и секций Recently. Весь плеер витриной не становится.

## Каркас — четыре вкладки (ЗАМЕЩАЕТ «Каркас» канона)

`TabView`: **Home · Медиатека · Папки · Поиск**. Мини-плеер — системный
`tabViewBottomAccessory` (без изменений). Отдельная вкладка «Плейлисты»
упраздняется: плейлисты переезжают на Home, категории — в «Медиатеку».

- **Home** — плейлисты + Discover + Recently (см. ниже).
- **Медиатека** — список входов: Артисты · Альбомы · Жанры · Годы · Все треки.
- **Папки** — как есть (локальная фича, у Apple Music аналога нет).
- **Поиск** — как есть, с полировкой (см. «Поиск»).

## Home (ЗАМЕЩАЕТ «Списки» канона в части Home)

Вертикальный скролл, сверху вниз:

1. **Плейлисты** — 2-колоночная сетка карточек. Смарт-плейлисты (Favorites,
   Top 25 Most/Recently Played) закреплены сверху, дальше пользовательские **по
   алфавиту** (префиксы источников — «ВКонтакте», «Spotify -», «Яндекс» —
   кластеризуются сами собой). Обложка карточки — **мозаика 2×2** из обложек
   первых четырёх треков; при <4 треках одиночная обложка/цветная заглушка.
   Ручное перетаскивание — возможная доработка на потом, не в этой фазе.
2. **Recently Played** — горизонтальная карусель трек-карточек (`lastPlayedDate`
   desc). Полезна с первого дня.
3. **Discover** — горизонтальная карусель трек-карточек (50 непрослушанных,
   логика `LMDiscover` без изменений). Раздел перестаёт быть плоским списком.
4. **Recently Added** — горизонтальная карусель трек-карточек (`dateAdded` desc).
   Оживает по мере докидывания файлов (при первой заливке даты близки).

**Трек-карточка** (единая единица для всех трёх каруселей): миниатюра альбома +
название + артист, тап = играть трек. Отдельных «альбомных» карточек не вводим.

## Медиатека

Список входов, каждый — push внутрь:
- **Альбомы** — 2-колоночная сетка карточек с миниатюрами.
- **Артисты** — список с круглыми миниатюрами.
- **Жанры / Годы** — простой список.
- **Все треки** — трек-лист с миниатюрами альбомов, алфавитный индекс сохраняется.

## Шов миниатюр (новый, общая зависимость всего рескина)

Обложки в базе лежат одним BLOB display-размера (`artwork_data` на `albums` и
`artists`) — тянуть их в списках дорого (~1.25 с на полную библиотеку). Вводится
отдельная миниатюра:

- Новая колонка `artwork_thumbnail` на `albums` и `artists`: ~140 pt (×3 =
  ~420 px), HEIC.
- Генерируется на скане; существующие обложки backfill-ятся **фоновой миграцией**
  по образцу v8 (`DMBackgroundMigration`, конвертация артворка в HEIC).
- Списки и сетки читают только `artwork_thumbnail`; полноразмерный
  `artwork_data` — исключительно детальные страницы и Now Playing.
- Трек-строки берут миниатюру своего альбома (ключ — `albumId`).
- Реализуется через существующий шов `PlatformImage`, без новых `#if os(...)`.

Автотест на шве: сборка миниатюры из исходной обложки даёт корректный
уменьшенный HEIC (в духе «тесты только на швах»).

## Детальные страницы — единый паттерн шапки

Альбом · Артист · Плейлист приводятся к общему виду: крупная обложка-хедер,
название/подзаголовок, заметный ряд **Play + Shuffle**, крупный сворачивающийся
заголовок, ниже — треки.
- Альбом: обложка уже 240 pt — добавить ряд Play/Shuffle и заголовок.
- Плейлист: хедер с мозаикой 2×2 + Play/Shuffle.
- Артист: фото/био уже есть — добавить тот же ряд действий.

## Мини-плеер

- **Compact**: тонкая **неинтерактивная линия прогресса** под строкой (как Apple
  Music).
- **Expanded / Now Playing**: полноценный скраббер (без изменений).
- Now Playing остаётся in-hierarchy оверлётом (уже сделано, коммит `801ff25`).

## Поиск

Почти не трогаем: сгруппированные секции результатов — это и есть Apple
Music-путь (сегмент-контрол он не использует). Полировка — выделить **Top
Result** первым блоком. Сегменты не добавляем.

## Крупные заголовки

Все верхнеуровневые экраны (Home, списки «Медиатеки», плейлист, артист, альбом)
получают крупный заголовок, сворачивающийся при скролле. Модалки и утилиты
(настройки, импорт) — inline.

## Порядок сборки (каждый шаг оставляет рабочий продукт)

**Слой A — рескин (структуру не трогаем):**
1. Шов миниатюр: колонка + генерация на скане + фоновая миграция backfill + тест.
2. Миниатюры в текущих списках: Все треки, категории, сетка Альбомов, список
   Артистов. Максимальный визуальный скачок на существующей структуре.
3. Крупные сворачивающиеся заголовки на верхнеуровневых экранах.
4. Тонкая линия прогресса в compact-мини-плеере.
5. Top Result в поиске.

**Слой B — структура (поверх похорошевшего продукта):**
6. Каркас: вкладки Home · Медиатека · Папки · Поиск; «Медиатека» с категориями.
7. Home: сетка плейлистов (смарт сверху + алфавит, мозаика 2×2) + карусели
   Recently Played · Discover · Recently Added из трек-карточек.
8. Детальные страницы: единый хедер с Play/Shuffle на Альбоме/Артисте/Плейлисте.

## Границы (не входит в фазу)

- Ручное перетаскивание плейлистов.
- Редакционные подборки / «Made for You» (нет источника данных — плеер локальный).
- iPad-раскладка, изменения воспроизведения, сети, швов путей.
- Новые `#if os(...)` вне четырёх швов и вне `iOS/`.

## Проверка

Симулятор и устройство — переходы, сетки, миниатюры, карусели, шапки. Автотест —
только на шве миниатюр. Обе платформы должны собираться (общие слои затрагивают
схему базы и модель).
