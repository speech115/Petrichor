# 00 — libraryContentsDiffer: перманентный рескан при отсутствующих файлах

**What to build:** `libraryContentsDiffer` (DMFolders) сравнивает **счётчики**
строк базы и файлов на диске: `stored.count == onDisk.count`, а затем идёт по
стороне базы. Если хотя бы один трек в базе не имеет файла на диске (файл
удалён — а строку база хранит намеренно: «пропавший файл делает трек
отсутствующим, но не удаляет его из плейлиста»), счётчики не сходятся
**никогда**:

- скан не удаляет строки для пропавших файлов (в `DMTrackProcessing` нет
  обработки «есть в базе, нет на диске» — только new/update/skip);
- расхождение не «залечивается» сканом → `libraryContentsDiffer` возвращает
  `true` вечно;
- каждый запуск и каждый возврат из фона гоняет полный фоновый рескан всей
  библиотеки (2758 файлов, метаданные, обложки). Приёмку это не ловит: скан
  фоновый и молчаливый, UI читает базу мгновенно (ADR-0001).

**Фикс:** проверка идёт только по стороне диска — новые файлы и изменённые
mtime дают `true`; отсутствующие файлы — **устойчивое состояние, а не
изменение**, и в сравнении не участвуют:

```swift
for (path, diskDate) in onDisk {
    guard let storedDate = stored[path],
          abs(diskDate - storedDate) <= tolerance else {
        return true
    }
}
return false
```

Счётчики и цикл по `stored` удаляются. Семантика совпадает с ADR-0001
(«перечитываются только затронутые файлы»): добавление и изменение ловятся,
удаление — нет (строка остаётся «отсутствующим» треком, возврат файла
оживляет её по mtime).

**Blocked by:** None — can start immediately.
