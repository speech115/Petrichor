# 04 — Подсветка Lyrics анимировалась тремя способами сразу

**What to build:** Переход подсветки на следующую строку должен быть ровным.
Сейчас на переходе «мерцает» и старая строка, и новая.

**Status:** resolved

## Причина

Три наложенных источника анимации на одно изменение индекса:

1. `.fontWeight(.bold)` на активной строке **переизмеряет текст**. Внутри
   `LazyVStack` это меняет высоту строки и сдвигает весь стек — под скроллом,
   который в этот момент едет к этой самой строке. Раскладка и скролл гонятся
   друг за другом.
2. `withAnimation(.spring)` вокруг `currentLineIndex = newIndex` в
   `updateCurrentLine` — транзакция, накрывающая и подсветку, и скролл.
3. Отдельный `withAnimation(.spring)` вокруг `proxy.scrollTo` в
   `onChange(of: currentLineIndex)` — вторая транзакция на то же изменение,
   поверх первой.

## Решение

Вес шрифта постоянный (`.semibold` у всех строк), подсветка несётся только
`opacity` и `scaleEffect` — ни то, ни другое не трогает раскладку. Смена индекса
пишется без `withAnimation`; подсветка и скролл объявляют свои анимации сами и
каждый по одному разу.

- [x] Один вес шрифта на всех строках
- [x] Подсветка — `opacity` + `scale`, без `foregroundColor`
      (см. ловушку с `Color.secondary` в тикете 03)
- [x] `withAnimation` из `updateCurrentLine` убран
- [x] У подсветки и у скролла по одной собственной анимации
- [x] `reduceMotion` отключает обе

## Чем закрыт

**Не измерением.** В фикстурной библиотеке симулятора нет тайминговых текстов —
панель показывает «No Lyrics Available», подсветке не на чем сработать.
Обоснование только по коду, приёмка — пользователь на устройстве 2026-08-09:
«lyrics норм, всё хорошо теперь».

Единственный тикет итерации без покадрового доказательства. Если понадобится
воспроизводимая проверка — нужен фикстурный трек с LRC в
`Documents/Music`.
