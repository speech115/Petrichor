# 03 — Строки очереди не нажимались и были наполовину невидимы

**What to build:** Тап по строке в Queue переключает воспроизведение на неё.

**Status:** resolved

## Причина

Обработчика не было вовсе. `playlistManager.playFromQueue(at:)` существует в
`Managers/Playlist/PMQueue.swift` и вызывался ровно из одного места —
`Views/Main/PlayQueueView.swift`, то есть только с макоси. У строки в
`NowPlayingQueuePanel` был `.contentShape(Rectangle())` — форма для нажатия без
самого нажатия.

## Найдено попутно

Строки показывали только название: исполнитель, длительность и номер позиции
не отображались. Проверено на чистой сборке — дефект существовал до этой правки,
пользователь про него не сообщал.

Причина не в вёрстке. Плеер задаёт тёмную схему через
`.environment(\.colorScheme, .dark)` — это значение SwiftUI, и оно не доходит до
trait collection, относительно которой `List` резолвит семантические цвета.
`Color.secondary` внутри ячейки резолвился по светлой схеме, то есть в почти
чёрный, и исчезал на тёмной панели. Название было видно, потому что своего цвета
не задавало и наследовало белый.

`.foregroundStyle(.secondary)` — иерархический стиль, он выводится из
унаследованного цвета, а не из trait collection, поэтому даёт белый с прозрачностью.

Правка сделана вместе с тапом сознательно: «Queue работает» звучало бы пусто на
строках, где видно треть содержимого.

- [x] Строка обёрнута в `Button` с `.buttonStyle(.plain)`, `onDrag` и
      `swipeActions` продолжают работать
- [x] `Color.secondary` → `.foregroundStyle(.secondary)` у исполнителя,
      длительности и номера позиции
- [x] Комментарий в шапке файла объясняет ловушку с trait collection
- [x] В симуляторе: тап по первой строке перевёл воспроизведение с 7-й позиции
      на 1-ю; номера, исполнители и длительности видны
