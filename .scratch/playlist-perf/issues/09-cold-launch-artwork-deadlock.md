# 09 — Холодный старт: deadlock и eager artwork

Status: resolved
Blocked by: 08

## Проблема

На холодном запуске счётчик песен мог долго оставаться нулевым, интерфейс
зависал, телефон нагревался, а локальные crash reports указывали на SwiftUI /
Combine. Живая выборка показала две связанные причины:

- lazy-кэш `LibraryManager` впервые читался из detached-задачи и публиковал
  `@Published` с фонового потока, пока main thread строил `HomeTabView`;
- iOS-кэш категорий до первого экрана загружал полные artwork BLOB примерно на
  511 МБ вместо метаданных и адресных миниатюр.

## Реализация

- Публикация состояния библиотеки возвращена на main actor, чтение БД остаётся
  вне главного потока.
- iOS загружает сущности без полных обложек; видимые строки получают
  миниатюры адресно.
- Artwork декодируется под размер отображения вне main thread, декодированный
  кэш ограничен.
- Повторный тап внутри готовой очереди использует существующий queue mirror;
  полноразмерная обложка догружается после старта аудио.

## Проверка

- iOS Simulator build/run успешен; старт сразу показывал 1505 песен.
- 66/66 тестов прошли.
- На iPhone сразу появились 2919 песен; `ВКонтакте` загрузил 1286 треков,
  прокрутка и быстрые переключения прошли без нового crash report.
- macOS compile-check прошёл с `CODE_SIGNING_ALLOWED=NO`; подписанную сборку
  блокировал отсутствующий upstream Developer ID certificate.
