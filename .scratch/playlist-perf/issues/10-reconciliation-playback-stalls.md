# 10 — Ложная реконсиляция и лаги во время воспроизведения

Status: resolved
Blocked by: 09

## Проблема

После первого ускорения интерфейс снова резко деградировал во время
воспроизведения. Логи физического телефона показали не обычную нагрузку
AVPlayer: приложение несколько раз параллельно сканировало все 2919 файлов,
пересобирало дубликаты и повторно загружало категории.

Причина: дата изменения файла читалась из SQLite неверным типом, поэтому
`libraryContentsDiffer` всегда видел изменение. Каждый launch/foreground мог
запустить новый полный цикл. Даже неизменившийся обход дополнительно разрешал
симлинки корня для каждого пути и занимал 2,5–12 секунд.

## Реализация

- Исправлен тип чтения mtime и допуск сравнения времени.
- `reconcileLibrary()` получил single-flight gate: второй foreground-триггер
  пропускается, пока первый не закончен.
- Корень контейнера вычисляется один раз, сравнение идёт потоково с
  utility-приоритетом.
- Загрузки regular/smart playlist также схлопывают параллельные запросы.
- Расчёт палитры Now Playing вынесен с main thread и кэшируется по artwork.
- Сравнение текущей очереди не включает тяжёлые artwork-данные.

## Проверка

- Два последовательных запуска на iPhone завершились `Library contents
  unchanged`, без новых batch-сканов.
- Проверка 2919 файлов заняла около 0,8 с вместо 2,5–12 с.
- iOS-тесты и Simulator build/run прошли; macOS compile-check без подписи
  прошёл.
