# Интерфейс iPhone — спека

Спека не дублируется здесь, чтобы не разошлась с оригиналом. Канон:

**`docs/superpowers/specs/2026-08-05-petrichor-ios-design.md`**, разделы
«Интерфейс» и «Порядок сборки», шаги 5 «Каркас интерфейса» и 6 «Списки и
навигация».

Проверенные факты по API iOS 26, на которые опираются тикеты:
**`docs/research/2026-08-05-ios-26-interface-apis.md`**.

## Решения, принятые до тикетов

- **`iOS/ContentView.swift` переписывается заново**, а не дорабатывается. Его
  каркас противоречит спеке почти во всём: свой плавающий плеер вместо
  системного аксессуара, `.sheet` с детентами вместо разворота, старый синтаксис
  `TabView` без ролей.
- **Вкладки строго по спеке**: Библиотека, Плейлисты, Папки, Поиск. Вкладка
  Home убирается — в спеке её нет. Флаг `showFoldersTab` уходит, Папки
  становятся постоянной вкладкой. Настройки — кнопкой в навбаре Библиотеки.
- **Очередь, тексты песен и настройки пишутся заново в `iOS/`.** Макошные
  `PlayQueueView`, `TrackLyricsView` и `SettingsView` на iPhone больше не
  используются.
- **`#if os(iOS)` из `Views/` вычищается по ходу**: каждый тикет, который
  переносит экран в `iOS/`, забирает с собой соответствующую ветку. Отдельного
  тикета на уборку нет — иначе он повиснет на всех остальных.

## Главный риск

`tabViewBottomAccessory` не проверен на iOS 27 beta, а от него зависит форма
всего каркаса. Поэтому он в тикете 01, а не в середине: если API окажется
сырым, откат стоит один тикет, а не шесть.

## Как работать

Фронтир — любой тикет, у которого все блокирующие закрыты. Один тикет за раз,
контекст между тикетами чистится.
